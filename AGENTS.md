# Repository working agreements

Complete the requested change and verify the behavior it affects. Use the repository's existing setup and relevant checks. If a check needs credentials, production access, or unavailable infrastructure, explain that limit and finish the independent work.

Read documentation relevant to the change: architecture for boundaries, data documentation for schema changes, and release guidance for deployment. Keep task-specific context near the code it governs. Preserve existing user changes.

Keep skills narrowly scoped, with concise descriptions and conditional references. Retain concrete project constraints; avoid generic process checklists and mandatory full-repository reading.

## Code Review Rules

Report actionable correctness, regression, security, or data-integrity findings with a concrete trigger and affected code. Distinguish verified behavior from an untested concern. Scale review and tests to the change; do not manufacture findings to fill a quota.
